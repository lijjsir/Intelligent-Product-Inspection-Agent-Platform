# PIAP 质量监督界面预览

本目录是独立的 HTML/CSS/JavaScript 预览，不改变正式 Vue 页面，不调用系统接口，不写数据库。

Git只保存预览源码。复制的公开原件、生成的facts.js和渲染截图保留在本地，不随代码提交；这些文件由prepare_assets.py及render_preview.py生成。

打开 `index.html`，用右上角的三个入口或侧栏切换。也可以直接打开 `index.html#intake`、`index.html#detail`、`index.html#risk`。无需安装依赖或启动服务。

## 三张效果图

- `renders/01-intake.png`：资料列表，标题与短摘录、资料类型、可辨识来源、关联对象、资料日期。
- `renders/02-source-detail.png`：报告详情，原件与事实摘录对照、原报告结论、来源与关联研判。
- `renders/03-risk-assessment.png`：研判台账与当前事项详情，证据、版本、状态及下一步操作。
- `renders/04-risk-detail-current-flow.png`：按当前正式逻辑修正的事项详情，保留研判结论、原始资料、可选验证、复盘报告、版本与复核五个标签页。
- `renders/*-mobile.png`：390px 窄屏参考。中等宽度也采用完整字段的记录卡片。

这不是一组仅供参考的绘制图片。三张图都来自本目录可运行代码，能验证搜索、资料类型筛选、关联状态筛选、原文展开、PDF 页码切换、原件放大、事项筛选与详情选择。未实现的正式业务操作会明确说明，不假装导入成功或复核完成。

## 设计决定

1. 保留既定导航：AI 对话下方是会议室；实验室检测在质量监督内；标准审核和知识资料独立。
2. 删除大幅说明卡片，保留一行功能说明和有用的上下文。
3. 列表负责定位资料。原文完整保留在详情中，长网址改成来源名称和域名链接。
4. 原报告事实、整理摘录、平台研判和人工复核分清，不把历史“不合格”当作当前产品结论。
5. 研判列表使用全宽，事项详情在下方；窄屏改记录卡片，不挤掉字段。
6. 下一步操作属于具体事项，不增加质监工作台或独立待办。

## 与原截图相比，哪些能落地

| 预览设计 | 当前依据 | 落地条件 |
| --- | --- | --- |
| 紧凑页头、动作层级、留白、颜色、字体、状态标签、窄屏卡片 | 普通 Vue/Element Plus/CSS | 可直接做前端调整，保留现有权限、路由、业务状态 |
| 列表只展示短摘录，详情保留原文 | `QualitySourceRecord.content` 已有完整内容 | 可直接做；默认短摘录应由原文截取，不能冒充模型总结 |
| 清楚的业务标题 | 当前无统一独立标题字段，内容为自由 JSON | 本预览标题由人工整理；正式版需确定标题字段、录入方式与旧记录回退规则，不能假定系统已自动抽取 |
| 来源名称、域名及完整链接 | `provenance.source_url/origin_label/publisher` | 可展示已有来源；缺失发布者时显示域名或“来源待补充”，不能只凭域名给“已核验”标记 |
| 产品与企业、原件、关联研判集中到详情 | `recordContext()` 已返回 objects、attachments、related_cases | 可复用，保留对象修改的版本检查与原因填写；列表可先用现有引用字段，不逐行并发请求上下文 |
| 日期明确标注“发布/签发/抽样/接收” | `occurred_at/received_at` 与部分资料 `provenance` 元数据 | 已知日期可显示；未结构化的发布日期需整理保存，不能把发布日期自动当作发生日期 |
| 原报告与事实对照、结果汇总卡 | 已有公开 PDF 与 `transcribed_values`；附件下载接口存在 | 本例能做。已另行补上正式资料详情中的鉴权 PDF 页图预览、页码切换及原件校验；不假定每份报告都有结构化结果 |
| 台账内证据、状态、版本、关联资料、独立复核入口 | `riskCases()`、`riskWorkspace()`、后台研判与复核接口 | 可复用；入口按权限和当前版本显示，点击后是核对表单，不是直接批准 |
| 全部资料/不同类型数量、事项状态数量 | 当前分页接口返回该查询的 total，未有统一分组统计接口 | 预览数字仅来自展示的5份材料/3个事项。正式版跨全部数据的分类总数需聚合接口，不能拿当前页数量当总数 |
| 按“对象待确认”、研判范围筛选 | 当前资料列表有类型/关键词/产品/企业筛选；研判列表有状态/关键词筛选 | 新的对象关联状态与范围组合筛选需补服务端条件，或者明确仅筛当前页；避免只过滤已加载的一页却声称筛全部数据 |
| 文件导入与重复识别 | 现有 previewImport/confirmImport、字段映射及重复识别 | 继续复用。若增加后台批量进度、可恢复上传等，需要另做接口和任务状态 |

## 不能由换页面实现的能力

- 缺失的仪器校准、重复原始测量、现售批次、整改复检数据，仍要真实业务材料补齐。
- 历史报告可以做资料复盘；不能仅靠新界面把它变成一次本平台重新检测，或当前市场风险结论。
- 原报告扫描页能如实显示；识别结果、复杂表格、公式和证据解释仍需专业核对，不承诺所有 PDF 全自动准确识别。
- 复核权限和独立性约束继续生效；不新增“自动审批成功”等虚假状态。

## 复现

```powershell
python design-previews/quality-20261023/prepare_assets.py
python design-previews/quality-20261023/render_preview.py
```

第二条命令需要本机已有 Python Playwright 和 Chromium。`renders/checks.json` 记录桌面、平板和手机的布局检查及交互检查。没有请求本地正式服务或远程服务器。
