# 无真实检测资料时的本地演示

日期：2026-10-19。演示重点是质量风险分析与辅助决策；实验室作为可选补证分支。

## 准备

1. 在项目根目录执行 `python deploy/quality-demo/manage.py up`，启动已有隔离演示环境。无需提供真实样品、测量文件或校准资料。
2. 打开 <http://127.0.0.1:15174/login>，以 `demo_analyst` 登录。独立复核使用另一个账号 `demo_reviewer`；`demo_admin` 用于管理，不能代替专家编写、复核或查看报告。密码从本地忽略文件 `.codex_tmp/piap_quality_demo/accounts.json` 读取，不写入演示材料、不分享账号文件。
3. 打开“质监工作台”，点击“从案例导览开始”。导览仅在服务端标记的演示环境、具备业务资料读取权限的专家账号下显示，不能通过 URL 参数启用。

导览按服务端指定编号查找 `DEMO-QS-001`，显示实际保存的资料数、最新版本和状态，不用固定“全部完成”标识。没有初始化、资料被撤回、编号不匹配或权限变化时，页面说明问题并清空案例入口，不跳转到列表第一条记录。

## 六步讲解

| 顺序 | 点击入口 | 重点说明 |
| --- | --- | --- |
| 1 | 数据接入 | 查看同一产品的模拟投诉、舆情及原始出处。对象、时间、附件保持来源关系，未知信息不代填 |
| 2 | 异常发现 | 查看两个完整七日窗口、数量规则及来源记录。上期为零不计算增长百分比，线索不等于风险结论 |
| 3 | 风险研判 | 查看已保存结论、引用证据、缺口、限制、历史版本和复核状态 |
| 4 | 协同复核 | 从事项查看同单位协同及其绑定版本，说明公开意见如何回到事项；私聊不自动变成报告依据 |
| 5 | 抽查建议 | 查看核查对象、方向和限制；演示建议不进入正式抽查计划、不自动检测 |
| 6 | 分析报告 | 查看已固定报告和历史快照，说明其对象、证据、结论、限制、复核及建议。需导出时使用已有 PDF/Word 功能 |

每个业务页顶部提供“返回演示导览”，方便继续下一步。编号表示讲解顺序，不表示软件检测、实际采样或业务确认已经完成。

导览还会从当前可访问的报告中查找“本报告对应研判版本选择暂不验证”的示例。找到后可直接打开，历史版本明确标为历史快照。检查命令会列出实际版本号，不依赖固定版本。

## 怎样说明实验室

- **暂不验证：无需任务。** 当前没有实测条件时，记录原因和证据缺口。可以完成有边界的人工演示分析，不能因此获得正式风险确认。
- **引用已有报告：无需平台任务。** 有报告时核对来源与对象后关联。当前演示只用明确标注的模拟报告，不把模拟资料当作真实检测证明。
- **组织新的检测：需要任务。** 真实工作须具备产品、样品、原始测量、设备历史校准与适用标准。当前演示不创建实际任务，也不启动设备或模型；已有隔离软件测试覆盖任务准备到结果回流，但实际检测仍待真实资料验收。

讲解时可打开“查看本事项可选验证”，说明三条路径的关系。暂时没有真实检测资料不影响展示质量监督主线。

## 重复演示与两账号操作

查看导览、打开已有研判、报告或历史不需要重置数据。导览只发起读取请求，不自动创建草稿、提交、复核、协同、建议、任务或报告。市场监控页面沿用现有扫描逻辑，重复扫描不等于新增风险事项。

若需要实际展示填写和复核，由编写专家在原事项中手动创建下一版、引用现有模拟资料并保存、提交，再切换到另一位专家独立复核。新增资料后应创建新版并重评；旧报告继续作为当时快照。不要删除旧版本或把初始化脚本当作回退工具。

## 可重复检查

在项目根目录运行：

```powershell
python deploy/quality-demo/verify_walkthrough.py
python frontend/tests/demo_walkthrough_live_browser.py
```

第一个命令读取现有本地演示数据并检查两位专家、来源标识、已有跳过验证报告及任务/正式计划边界，不初始化或代替复核。第二个命令用 Chromium 检查六步往返、历史报告、可选验证、刷新、权限失败恢复、分页定位、桌面与移动视口。测试中的延迟和拒绝响应仅用于验证界面，不修改真实业务资料。

结果、截图写入忽略目录 `.codex_tmp/piap_quality_demo/walkthrough-*`。这些命令不调用真实模型或设备。完整检测软件链路另见 [样品与测量回流验收](LAB_MEASUREMENT_HANDOFF.md)，真实资料待验收项目见 [未完成清单](REMAINING_VALIDATION.md)。
