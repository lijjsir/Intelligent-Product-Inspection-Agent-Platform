## 已接通的路径

1. 在最新已提交的研判版本中打开“协同讨论”，选择另一位同单位专家作为负责人，按需增加参与专家并填写协同问题。
2. 系统固定事项、研判 ID、业务版本、文字及依据指纹，原子创建受限会议、成员、协同工作项及其关联记录。一版只建立一场协同，重复点击返回原记录。
3. 负责人在原协作中心接收请求，参与专家在原会议室公开讨论。会议标题下持续显示固定版本，提供返回原事项的入口。
4. 会议公开讨论、工作项评论直接引用原消息返回事项页面；处理说明也保留在原工作项中。私聊不进入事项的公开意见。
5. 请求可以从待处理变为已接受，再完成。完成协同不会调用独立复核接口，也不会更改研判结论、证据或版本。

协同房间中的模型、主动参与、记忆/知识发布与检测执行不在本轮流程中。房间保持人工讨论方式，公开文字即使提到会议 Agent 也不会触发模型调用。

## 关联与权限

- 只允许指定演示组织中的有效专家，以及现有质量业务、业务资料读取、会议、协作权限。候选参与人来自同一组织的有效专家。
- 同时校验发起版本是最新锁定内容、当前依据仍有效；历史或过期版本不能新发起协同。已有讨论仍固定于原版，补证/新版不会改绑旧讨论。
- 房间与工作项均使用明确成员范围。会议码不能自动增加受邀范围；普通会议和协作入口也检查研判协同成员及权限，不能通过原生路由绕过。
- 事项、版本、负责人、参与范围和人工讨论方式不能从通用会议设置改写。直接删除关联会议、工作项或请求受到保护，保留原版追溯。
- 演示协同发言不能提交正式知识候选；会议记忆发布也继续被拦住。演示讨论不是正式风险证据或复核结论。
- 真实资料、真实模型、跨单位协同、演示抽查建议尚未扩展或验收。

## 数据与接口

未新增数据库表。使用现有 `meeting_rooms`、成员和消息表、`collab_*` 工作项/回执/评论表，以及 `supervision_records` 的专用 `risk-collaborations` 类型保存固定关联。原文和讨论消息各存一份，以 ID 引用。

会议业务上下文增加 `risk_case_id`、`risk_assessment_id`、`risk_assessment_version` 和 `execution_mode`。该上下文只能由研判协同入口关联。版本链接可恢复指定历史研判；“返回最新版本”可回到当前版。

新增接口统一 `/api/v1` 前缀：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /risk-collaborations/participants` | 同单位有效专家选项 |
| `GET /risk-cases/{id}/collaborations` | 当前专家参与的本事项协同 |
| `POST /risk-cases/{id}/collaborations` | 校验版本及依据后幂等发起 |
| `GET /risk-collaborations/{id}` | 固定关联、当前有效性和公开返回意见 |

创建输入包含指定研判、依据指纹、请求 UUID、负责人、可选参与人和协同问题。组织行锁、事项行锁和现有组织/kind/code 唯一约束保证并发重复请求复用同一关联。讨论、回执和评论复用原会议/协作接口；处理说明保留在协同请求中。

## 本地验收

在已完成阶段 4A 的演示案例上执行：

```powershell
python frontend/tests/risk_collaboration_phase4b_live_browser.py
python deploy/quality-demo/verify_phase4b.py
```

浏览器先完成实际发起流程，再由接口验证并发重复请求和失败路径。重复运行会复用当前记录和消息，不重复建立会议、资料或研判版本。

验收覆盖：两个真实账号、发起和固定版本、原生会议讨论、原生请求接收/完成、返回事项与刷新恢复、公开/私聊隔离、未受邀账号持会议码被拒、错误负责人/旧版本被拒、改绑/删除被拒、原研判和资料不变、桌面与手机布局。没有模拟 API 或模型成功。

SQLite 回归额外覆盖跨组织/失效参与人、退出成员后无法继续访问、补证与新版后旧会议仍指向原版、模型/正式知识入口被阻止，以及原有普通会议、协作与知识行为。
