# 抽查、协同与检测入口分页完善

日期：2026-10-19（北京时间）。本轮只修改本地工程，没有推送或更新远程服务器；目录菜单保持不变。

## 已修复的问题

| 入口 | 原问题 | 当前处理 |
| --- | --- | --- |
| 正式抽查及通用业务表单 | 设备、计划、样品、任务、标准等选项只读取前 200 条，前端再过滤；当前有效风险候选一次全部校验 | 按编号/名称在服务端搜索、分页；任务样品先按任务筛选，计划只提供已批准版本，正式风险候选仍完整执行真实证据和独立复核门禁。已选项独立核对，超过 20 个时分批读取，不降低原有业务选择上限 |

| 撤权与异步 | 旧协同列表、原生工作项和重复发起可能未统一核对会议室绑定；迟到请求可能干扰新上下文 | 旧列表、新分页、直接读取、重复发起统一检查有效成员和协同绑定；停用账号不能成为新处理请求目标。分页、事项切换和原生执行表单读取用请求代次保护，过期失败不弹全局错误提示 |

旧 `MeasurementPanel` 的先截断再按任务筛选问题也已修复，但它没有被重新挂载到实际任务页。本轮继续使用现有原生执行流程，没有额外引入第二套检测操作入口，也没有扩建设备管理。

## 接口与数据约定

- `GET /api/v1/quality-supervision/options/{key}`：供现有业务表单选择地区、设备、企业、已批准计划、任务样品、任务、标准及有效风险候选。支持 `page/size/keyword/task_id/selected_ids`；页大小最多 50，已选编号每次最多 20 个。
- `GET /api/v1/quality-supervision/laboratory-summary`：组织范围内的会话状态及在线设备聚合统计。通用会话、样品列表新增 `task_id` 条件，查询先筛选再分页，名称和系统编号均可检索。
- `GET /api/v1/inspection-execution/tasks/{task_id}/reference-pages/{sessions|samples|policies}`、`POST .../context-selection`：前者返回有界选择项；后者只读取所选上下文，不写业务数据。保留初始预览池以兼容现有上下文结构，后面的已选记录单独补入。平台实体只能从同任务/同组织读取，策略仍须是已发布且适用的版本。执行创建及复核没有取消来源核验、版本指纹和独立复核规则。
- `GET /api/v1/inspection-execution/run-pages`：当前任务执行列表的编号搜索与分页。
- `GET /api/v1/risk-sampling/pages/{candidates|suggestions}`、`GET /api/v1/risk-cases/{case_id}/collaboration-pages`：业务页面使用的独立分页入口；历史演示数据缺少环境字段时仍按演示解释，正式与演示继续隔离。
- `GET /api/v1/risk-collaborations/participant-pages`、`GET /api/v1/collab/target-pages/{user|meeting_room}`：专家、接收成员和已加入会议室的分页选择及当前授权检查。
- `GET /api/v1/collab/work-item-pages`、`GET /api/v1/collab/work-item-detail/{kind}/{item_id}`：混合工作项分页和独立详情。列表明确按创建时间排序；修改状态后记录的位置不会因修改时间而跳动。

抽查建议和工作项采用加密游标，绑定账号、组织、运行环境或角色、筛选条件和页大小，一小时过期。每次请求最多扫描两页候选（至少 20、最多 100 条），当前权限另行核对；某页因不符合条件而为空时，仍可继续下一页。页面有回到首页入口。不伪造授权过滤后的全局总量。

旧数组接口继续保留，内部冻结完整快照等现有调用未被静默截断；新业务页面使用新的有界接口。协同旧概览计数仍是有上限的兼容结果，界面改为“至少 N”，分页区域只显示本页数量，不能将它当作精确总数。

## 验收证据

- `backend/tests/test_remaining_pagination.py` 新增 **8 项**隔离集成检查：243 条同任务会话/样品、231 份执行草稿、混合工作项、超过 200 人的专家选择、206 份抽查建议、原生会话/样品超过 200/500 的选择、HTTP 参数限制，以及前 200 条之外的发布策略。检查包括稳定排序、深链、任务/组织范围、停用与撤权、游标变更、创建执行和独立复核。所有大数据量资料只在测试数据库中使用。
- 相关后端回归一轮 **148 项通过**；新增用例与协同/建议的补充复验 **32 项通过**，测试数量有重叠，不能相加作为不同用例总数。原始结果在忽略目录的 `remaining-*.log`。
- 前端全量 **48 个文件、175 项通过**，新增存储层迟到失败及持续连接刷新保持筛选/游标的反例；类型检查、Lint、构建通过。
- `frontend/tests/remaining_pagination_browser.py` 使用完全隔离的 API 响应，验证实际任务页的旧会话深链、超过 500 条的样品选择和上下文刷新、建议/工作项深链不在当前页、跨页保留、返回来源事项、接收专家搜索与撤权，以及 390px 移动视口。没有写入业务数据，不把响应中的模拟内容表述为真实执行完成。
- `quality_supervision_workspace_browser.py` 原有正式业务界面契约继续通过，包括可选验证、原生检测结果回流、冲突、去重和撤回。
- `deploy/quality-demo/verify_remaining_pagination.py` 在真实本地 MySQL API 上只读比较新旧列表、混合工作项与直接读取、角色及接口参数边界。两位专家均能看到原案例的 2 份建议和 1 个当前候选，没有因分页漏掉旧记录。
- 原阶段五接口与浏览器导出复验通过：案例仍为 **16 条资料、6 个研判版本、3 份报告**；PDF/Word 下载、旧快照、独立复核及正式候选隔离保持。演示环境没有实际检测任务，因此真实原生任务的大规模选择与复核在隔离数据库及浏览器契约中验证，不能冒充真实检测验收。

## 仍待专项验收

本轮没有宣称全平台每个历史接口均已分页。原生单会话原始测量的长列表、报告候选、标准要求列表、历史协作会话，以及非本轮业务表单的完整产品目录等仍需单独梳理；当前原生测量预览上限为 5000，界面在达到上限时保留资料可能不完整的提示。精确协同概览计数、大快照和生产负载、长时间持续连接、实体手机与 Safari 仍需验证。

真实授权数据、标准适用性、仪器和实际模型推理质量继续按 [未完成验收清单](REMAINING_VALIDATION.md) 处理。本轮没有调用真实模型或仪器，没有增加正式计划、自动检测、执法或整改动作；没有修改数据库表结构和原有 `.env`。
