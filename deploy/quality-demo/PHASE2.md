# 阶段二：资料与对象关联

## 已实现

- 投诉、舆情、检测资料共用资料台账和受理接口；标准、知识入口复用原页面，不另存标准副本。
- 表单从本组织的有效档案中选择企业、类别和产品，支持搜索；只返回名称和标识，不开放完整档案。
- 原始企业、产品描述分别保存。名称相同不会自动匹配档案；不知道的发生时间和对象保持未知。
- 资料详情展示当前档案引用、原始出处、发生/接收时间、数据性质、附件和引用该资料的研判事项。
- 详情地址保存资料 ID，刷新及资料/研判往返使用同一记录；结构化导入保留原始行和行号供核对。
- 确认或调整对象关联需要填写依据，并记录操作人、版本、时间和前后档案名称；原文、附件、发生时间、受理 ID 和原始内容指纹保持不变。
- 并发版本不符返回 409，界面保留依据并提供重新核对操作。历史确认结论不被覆盖；来源变化后需要重新核验。

## 去重与访问边界

同一组织、同一上传人、同一文件名和内容复用附件 ID；不跨私人上传者复用。仍有效的附件若仅丢失物理文件，可以用相同内容恢复；已撤回附件不能通过重复上传静默恢复。

同一来源的相同材料按原有内容指纹复用。手工/文件两个内置接入渠道，在**出处与外部编号都明确且材料相同**时复用原记录，文件导入过程仍留有独立批次记录。未知出处、不同私人提交者和独立外部来源不会擅自合并。

复用记录保留首次受理来源，不覆盖原始出处。导入原始行和行号随批次留存；首次通过文件受理的资料也可在详情中核对原始行，此处不宣称整份结构化文件已经归档。

跨组织、已停用或归档的档案不可作为新关联；历史引用显示不可用。只因受派而能读取别人的资料，不代表可以修改其关联。演示资料与导入预览继续由后端强制标记为模拟资料，不进入正式风险确认。

## 接口

- `GET /api/v1/quality-data/reference-options`：精简档案选项，支持 `keyword` 和 `limit`。
- `GET /api/v1/quality-data/records/{id}/context`：原记录、档案状态、附件和相关研判。
- `PATCH /api/v1/quality-data/records/{id}/objects`：完整提交三个对象 ID（未知可空）、`expected_version` 和 `reason`。
- 资料列表新增 `enterprise_id` 筛选，保留既有 `product_id` 等参数。

关联历史使用既有 JSON 字段，不覆盖历史资料、研判快照或新增另一套主档案。演示建库补齐全部 ORM 模型注册，增加此前漏建的通知空表，未增加协同业务流程。
