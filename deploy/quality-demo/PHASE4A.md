## 操作流程

1. 研判专家创建人工演示草稿，整理演示结论、判断依据、引用资料、证据缺口、限制及后续建议。关注等级默认未知，发生概率始终为未知。
2. 点击“保存演示草稿”后可刷新恢复；保存本身不会提交。保存含乐观修订校验，冲突时保留未保存文字，并提供明确标注的重新加载按钮。
3. 点击“提交本版演示复核”后，该版内容锁定。至少填写结论、依据、限制、证据缺口并引用一条本事项原始资料，才能提交。
4. 切换到另一位专家，核对同一版本，填写复核意见，再选择“演示复核通过”“退回修改”或“退回补证”。不能复核本人编写并提交的版本。
5. 新增资料、证据片段、对象改绑、来源授权变化、对象停用或附件原件变化都会重新核对依据。旧版内容、提交人与复核意见保留；过期版本不能通过复核。新增版本会重新冻结当前依据。

退回后也创建新版，不覆盖原版。复核人只能填写意见与决定，不能直接改写提交人的判断。

## 服务端边界

- 演示流程仅在服务端启用 `quality_demo_enabled`、指定演示组织及质监业务启用时开放。前端参数不能开启。
- 创建、编辑、提交和复核均要求有效专家账号及现有质量业务、业务资料读取权限；管理员可查阅，但不代替专家编写或复核。
- 仅接受明确标注 synthetic 的资料与证据，检查本组织档案、来源状态、授权、片段集合、附件原件 SHA-256 和大小。模拟资料也不能引用丢失或变化的附件。
- 新状态为 `demo_draft → demo_submitted → demo_reviewed`，或退回 `demo_revise` / `demo_request_evidence`。不存在自动升级为正式 `accepted` 的路径。
- 正式复核接口继续执行原有真实证据规则；演示事项、演示版本不能通过正式确认。演示环境的旧模型分析入口明确提示使用人工演示流程，不发起模型调用。
- 本轮不生成正式抽查候选、正式统计、知识发布或检测任务。全部页面持续说明人工演示、模拟资料及概率未知。
- 初始化仍只创建资料和未复核草稿，复核始终通过两个不同账号显式完成。重复初始化不重置已提交的版本与人工意见。

## 版本与并发

沿用 `quality_risk_assessments` 表。业务版本记录整版结论与冻结依据，JSON 内的修订号负责草稿保存和状态变更的并发检查，无需升级正常业务库。

创建草稿需要最新基准版本 ID、当前资料集合指纹和请求 UUID；相同请求重试复用原草稿。保存、提交及复核均绑定指定版本与修订号，陈旧操作返回 409。演示业务在组织和事项行锁下读取当前版本，避免 MySQL 旧快照造成并发覆盖。

冻结信息包含事项范围、来源集合、资料内容及对象引用、证据片段、来源状态、档案可用性和附件校验值。服务端保存完整快照，公共工作区仅返回操作所需的指纹、文字和操作记录，不返回文件存储定位。

## 新接口

统一前缀 `/api/v1/risk-cases/{case_id}`：

| 方法与路径 | 用途 |
| --- | --- |
| `POST /demo-drafts` | 基于当前最新版本及资料指纹创建新草稿；请求编号保证重试幂等 |
| `PATCH /demo-drafts/{assessment_id}` | 本版编写人保存尚未提交的内容 |
| `POST /demo-drafts/{assessment_id}/submit` | 提交指定版并锁定内容 |
| `POST /demo-drafts/{assessment_id}/review` | 另一位专家对指定版给出演示决定和意见 |

现有 `/workspace`、`/risk-assessments/{id}` 增加演示上下文和当前依据核对结果，原正式业务字段与路由保留。

验收记录与截图位于 `.codex_tmp/piap_quality_demo/phase4a-*`。重复验收优先读取已完成的验收记录，不重复接入补证或创建空版本；如继续人工编辑了案例，验收会保留这些进展。
