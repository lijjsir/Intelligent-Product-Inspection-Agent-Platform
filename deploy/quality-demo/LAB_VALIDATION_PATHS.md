# 实验室验证三条路径与任务衔接

日期：2026-10-19。本轮仅修改本地代码，目录菜单不变，没有远程部署或 Git 推送。

## 从哪里进入

- 专家打开“风险研判”的具体事项，进入“可选验证”。
- 或打开左侧“实验室检测”，选择来源事项；正常业务模式下，风险事项验证区域默认展开。

验证始终关联来源事项及研判版本。当前支持在已有草稿、待补证或待复核版本记录申请，无须先确认最终结论。尚无研判版本时会提示先创建草稿；独立检测任务也可以按原有任务入口准备，之后再关联事项，不生成虚假的研判版本。

## 怎样选择

| 路径 | 需要任务吗 | 操作与输出 |
| --- | --- | --- |
| 暂不验证 | 不需要 | 写明理由，保存安排。页面隐藏报告提交和任务结果回流操作 |
| 引用已有报告 | 不需要本平台任务 | 保存申请后接入报告。服务端核对来源申请，带入对象供人工核对；未知时间、批次和单件继续留空。保存资料后回到事项，明确选择资料并关联回流 |
| 组织新的检测 | 需要 | 保存申请后，选择同一产品的已有任务，或点击“从事项创建验证任务”。核对产品、批次/单件、目的和现有标准配置后确认，创建待执行任务，进入原有任务执行页面 |

引用报告只展示当前授权范围内、对象匹配的资料。事项已限定批次或单件时，报告引用也必须一致；不能把同产品的另一个批次直接当作本事项验证。带入的对象是待核对引用，提交前须人工确认与原文一致；该声明不代替报告真实性、原件或专业复核。

资料保存不会自动关联事项。回流是单独的明确操作，复用原资料和附件记录，不复制为另一个风险事项。回流后应创建新版研判，再按规则独立复核，更新协同、建议和报告。

## 新任务如何回到来源

新建任务在同一数据库事务中保存任务、来源验证关联、资源编号及审计信息。创建后状态为“待执行”，不调用执行器、模型或设备。

任务页展示来源事项、原研判版本和验证目的，提供“返回来源事项验证与回流”。来源关联经过服务端校验，刷新或从任务列表重新进入也可恢复。用户从另一个已关联事项进入同一任务时，按当前来源请求核对，不任意回退到其他事项。

实际原生检测结果仍须经过专业独立复核，才能在事项中选择回流。它不是风险研判的最终复核；回到原事项后，仍需新版研判及独立风险复核。

## 状态与权限

- 新界面明确提交 `verification_path=skip/report/task`。复核前的记录使用 `validation_planned`（演示为 `demo_validation_planned`），`request_stage=preliminary`。记录申请、引用材料或创建任务均不修改研判的确认、信任等级和复核状态，不进入正式风险确认或抽查候选。
- 只有当前版本可以新建验证安排。原安排编写人可以修改未冻结安排或创建任务；已有任务创建记录或回流后，原安排保留，新的安排进入新版本。
- 创建任务须有同组织的有效具体产品及类别；企业或类别不能冒充具体检测产品。对象、资料或版本变化时要求重新保存安排；标准配置必须属于本单位且仍有效。实际执行仍须核对已发布检测要求及适用范围。
- 创建接口使用请求编号、输入摘要、关联修订号和资料指纹；重复请求复用原任务，换参数不能静默再建一个。失败时任务与关联共同回滚，不留下未关联的准备任务。
- 来源被撤回、关联版本不可访问、账号停用、跨组织或任务编号不匹配时，来源读取和创建被拒绝。前端清空旧来源和返回入口，不将第一条记录当作替代。
- 演示环境仍只用于模拟资料和流程，不允许创建实际检测任务。“组织新的检测”在演示界面显示为不可选，并说明原因，不能靠前端参数开启。

旧客户端只发送 `mode=skip/verify` 时继续使用原有独立复核门槛。旧验证记录不自动补写新字段，也不改写历史报告的快照。新增状态只用于验证安排，正式报告、协同和抽查建议的真实证据及独立复核门禁保持。

## 新接口

- `GET /api/v1/risk-laboratory-verifications/{link_id}/intake-context`：读取经核对的报告接入来源和对象引用。
- `GET /api/v1/risk-laboratory-verifications/{link_id}/task-preparation`：读取任务准备信息及不满足条件的原因。
- `POST /api/v1/risk-laboratory-verifications/{link_id}/tasks`：确认创建并关联任务；提交关联修订号、资料指纹、请求编号、标准配置编号和优先级。
- `GET /api/v1/risk-laboratory-verifications/{link_id}/task-origin?task_id=...`：在任务页核对来源事项和版本。

使用现有验证记录 JSON 和任务元数据，没有新增数据库表或迁移。任务详情增加可选的来源验证编号，后续读取仍检查服务端真实关联，不信任 URL 或客户端元数据。
